## Everything flagged across these pages, in one place

- `road_type` is required by the API and described as important for Nepal accuracy, but is never used by the actual model - see `03-schema-vs-model-mismatch.mdx`.
- `vehicle_type: "suv"`/`"van"` and `weather_condition: "snow"` all pass schema validation but fail at prediction time with a `500` - see `03-schema-vs-model-mismatch.mdx`.
- The README's own example request (and `test_api.py`'s requests) omit `road_type` and would be rejected by the current schema - see `01-overview.mdx`.
- The database layer (`app/database.py`, `app/models.py`, `create_tables.py`, `seed_database.py`, `railway_setup.py`) is fully implemented but entirely disconnected from the live app - see `05-the-unused-database-layer.mdx`.
- `Procfile`'s `release: python railway_setup.py` step will fail if `DATABASE_URL` isn't set, which could block deployment even though the web process itself no longer needs a database - see `05-the-unused-database-layer.mdx`.
- The README's "90% accuracy" claim isn't backed by any number recorded in this repository - see `01-overview.mdx`.
